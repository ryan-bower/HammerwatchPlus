2. **HIGH, R-27: the all-favorite empty state does not explain the filter.**

   no explanation or next action. Proposed fix: when the enabled feature filters
   a nonempty bag down to zero rows, say that favorites are protected and can be
   unfavorited in the inventory. Retain vanilla text for a genuinely empty bag
   and when the feature is off. Add source and controlled-engine checks.

## Decisions and evidence

- Layout: reuse the bag's existing action hints; no new panel competes with gear.
- Typography: reuse `gui/fonts/hw8.fnt` for the corner marker, matching item text.
- Color: the text marker sits on an opaque black backing so rarity artwork cannot
  obscure it. Intended white-on-black contrast is 21:1, computed with the skill's
  contrast checker. Actual rendered glyphs have not been captured or measured.
- Spacing: keep the existing item grid and hint ordering; Favorite has action
  order 5, before destructive/movement actions. Resolution fit is unverified.
- State: **F** is a persistent status mark, not color-only feedback; the hint
  changes from **Favorite** to **Unfavorite**. The marker is not a second button.
- Motion: none added; the existing item hover/focus behavior stays in place.
- Scope: sale protection only; intentional salvage and trading remain available.
