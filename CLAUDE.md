# HammerwatchPlus

Co-op mods for Heroes of Hammerwatch II (`mods/`), and GameLab (`gamelab/`), the harness
that boots the real game to test them. Current status is in `docs/status.md`.

## Hard rules
- Boot the game only with `uv run python -m gamelab run <scenario> --mode lab`. The CLI
  defaults to visible `watch` mode, so always pass `--mode lab`. Run `python -m gamelab doctor`
  first on a new machine or clone. Launch the real install only when the user asks (`/run`).
- Never touch the user's install, its config, Steam or local saves,
  `%LOCALAPPDATA%/HeroesofHammerwatch2`, or the install's `res/` unless asked. Keep every
  launcher isolation check on.
- No real input or focus changes: no `SendInput`, `keybd_event`, `mouse_event`, `SetCursorPos`,
  `SetForegroundWindow` or `bring_to_front`. Use GameLab's posted input and in-engine commands.
- One GameLab run at a time, machine-wide. Don't edit `mods/`, `gamelab/` or `tools/` during a
  run or batch; stage drafts in the ignored `gamelab/results/`. Scenario-owned `write_*_file`
  steps are the one exception, and they restore what they change.
- A non-zero exit is a refusal to diagnose, not to work around: 2 preflight, 3 build mismatch,
  4 lock held or dirty teardown, 5 INVALID, 6 TIMEOUT. Never bypass a gate, and never reset
  another agent's run.
- Don't re-pin a changed game build or restore real saves to make a test pass.
- Preserve unrelated edits and the owner's balance and design decisions.

## Evidence
- Read `run.json` (verdict, assertions, error, teardown) before drawing any conclusion. A failed
  setup is not a gameplay bug. Look at screenshots before describing them. Keep failed and
  flaky trials.
- Label the evidence: source review, setup, forced-state measurement or ordinary gameplay.
- Cite the pinned build, run ID and source revision. A past pass is not a pass on current source.

## Where things are
- Game scripts: `gamecode/sdk/hoh2/scripts/` (AngelScript). Data: `gamecode/datatables/*.sval.json`.
  Both are generated by `tools/bootstrap.py`.
- Mods: `mods/<id>/`, conventions in `docs/modules.md`, hooks in `docs/hooks.md`.
  Mods are enabled per save via `gamelab/hps.py`.
- Lifecycle: mod constructors run when `levels/town.lvl` (the menu) loads; `UpdateFrame` ticks only
  after a session starts (`docs/RE_NOTES.md`). Logs and mod stack: `docs/MODDING_NOTES.md`.
- GameLab: [quickstart](gamelab/README.md), [regression guide](docs/qa/REGRESSIONS.md),
  [full reference](.claude/skills/gamelab/SKILL.md). Run output goes to
  `gamelab/results/<time>-<scenario>-<mode>/`.
- Probes: add a read-only, capped `RegisterVerb` in `mods/gamelab-probe/scripts/GameLab/Probe.as`
  plus a `{"do": "gl", "verb": ...}` scenario step. All verbs: `docs/generated/verbs.md`.
- Class planner: `planner/` (`python -m planner`), records in `planner/data/<collection>/<id>.json`.
- Tools: `tools/` top level is build, deploy, saves and release; `tools/generate/` the `make_*`
  content generators; `tools/hoh1/` the HoH1 importer; `tools/art/` art pickers and fonts.
- Docs index: `docs/README.md`. What each module does: `mods/README.md`.

## Before you finish
- `python scripts/test.py` (pytest, the verb list and the settings config; CI runs the same).
- If you added or changed a verb, run `python tools/list_verbs.py` first.
- Add a dated entry to `docs/status.md` and the notes to `docs/RE_NOTES.md`. Keep the current
  checkpoint separate from history, and state unfinished work plainly.
