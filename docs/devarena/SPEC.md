# Dev Arena: spec (agreed 2026-10-20)

A game-dev build of HoH2 for building and tuning **elite specs** (subclasses, e.g. Warden =
`ranger_nature`: base class + 1 active + 1 passive + stats). One release; built in the order
below so each piece rests on a proven one. Future, not now: bosses, mechanics, event triggers.

## UX (agreed 2026-10-20)

- **Dock:** right side, ~35% width (Loadout may widen to 45%). Tab bar: Tune, Loadout, Arena,
  Golem, Bench, Compose. Footer: last action, errors, "needs relaunch". Mini HUD top-left stays
  when the dock is closed: DPS, hits, A/B slot + version, bench state, preset, and any of
  god / no-cd / inf-mana while on. Clicks on the dock never reach the game. Dense debug style,
  game widgets, no art pass.
- **Apply (Q23):** live on slider release / Enter, deferred until the current cast ends. Every
  apply is a version (v1, v2, ...), Ctrl+Z / Ctrl+Y step versions, written to the override
  file at once; A and B slots hold pinned versions; F2 swaps.
- **Tune (Q24):** grouped cards. FEEL (castpoint, anim-length, blocking; locked for the
  auto-tuner), NUMBERS (each curve field: per-level cells, growth slider, sparkline, `*` pins;
  sub-skill overrides marked), REFS (units/projectiles: relaunch badge; buffs: live if the spike passes).
- **Loadout (Q25):** favorites row on top (one-click swap); left: preset browser
  (class > subclass > tier > variant, search) with compare ticks -> golem bench; right: build
  sheet (level, attributes, reqs off, gear, trinkets + set progress, skills + star budget,
  combo), changes vs preset marked, Revert / Save as variant. Edits open inline in place of the browser.
- **Arena (Q26):** floor info + Reset (F3) + NG+ + cull; spawn by **brush only** (pick a unit or
  encounter preset to arm, middle-click to place, Esc disarms); mob toggles freeze (stun) /
  unkillable / passive; me: god, no-cd, inf mana, speed, buffs on me; encounters single /
  pack 4 / swarm 13 with clear time, damage taken, deaths.
- **Golem (Q27):** go there (F4); profile + NG+, raw overrides marked, HP pool unit/1M/4M/10M (built: no custom pool, Golem.as GOLEM_POOLS);
  debuffs permanent or reapplied every N s; pull: rotation me / bot / replay, RNG mode,
  variants A/B, pulls each. Bot and replay runs are hands-off and interleave A B A B with a
  golem reset between pulls; any input aborts.
- **Bench (Q28):** A vs B with spread, TTK, pulls, verdict vs siblings; per-skill breakdown with
  an unattributed row; procs (fired, ICD-blocked); mana in/out, OOM time. Champion/challenger:
  "Keep B -> A" empties B. Discard, Send to auto-tuner, Promote to docs/bench, history.
  Agent auto-tuner proposals appear here as pending: accept or discard.
- **Compose (Q29):** name + owning spec; start from a template or a clone; cast block, on-start /
  on-cast actions, nested on-hit effects, raw tree for hidden fields; validation shown before
  apply; a composed skill **replaces a chosen slot** (default spec active) for the session and
  then behaves like any skill in Tune / A-B / Bench. "New spec" (clone a vanilla subclass) lives here.

## Happy paths (each one is an acceptance check)

- **HP1 feel tweak:** `dev-arena` with a preset, F1, Tune, Entangle, castpoint 250->200,
  release, applied between casts, cast, F2 to A and back.
- **HP2 golem tuning:** raise a damage-curve growth into B, F4, profile barracks elite NG+3
  4M, bot rotation, A/B x5, Start, Bench verdict, Keep B -> A.
- **HP3 build compare:** tick two variants in Loadout, compare -> golem bench, side-by-side
  results, save the winner as a favorite.
- **HP4 new spec:** clone Warden to a new spec mod, compose an active from the projectile
  template into the spec slot, HP1, HP2, auto-tuner on numbers fields, bench early/mid/end in band.
- **HP5 relaunch:** edit a REFS unit value, "needs relaunch", [Relaunch]; the arena reboots
  with the same preset, A/B slots, position, golem settings, and the dock reopens on the same tab. Required.
- **HP6 ship check:** cold boot at level 10, pick the new spec at the real Subclass Picker NPC,
  every field reads back, tooltip lint passes, report written.
- **HP7 agent-driven:** `devarena-autotune` scenario with spec, target and fields writes a
  proposal with bench evidence; it shows as pending in Bench; accept or discard there.

## Build order

1. Spikes: live skill rebuild (cooldown read back, bind damage), freeze (stun vs `m_frozen`), non-pausing overlay + in-session text input (fallback: sliders/steppers), mod class via `InstantiateClass`, buff retune, RNG reseed.
2. Tuner (curve editor, A/B, override file, export).
3. Loadouts + presets (+ headless validation, tooltip lint).
4. Golem room + benchmark.
5. Panels: timeline, slow-mo, proc inspector, resource/survivability, baseline vs siblings, bench bot.
6. Composer + subclass clone script + star-budget check.

## Known engine facts (from code reading, 2026-10-20; spikes will verify)

- Level N params = `{upgrades[N-1], base}`; no cascade. Sub-skill params are inserted first and
  override (`PlayerBase.as:165-221`).
- `cooldown = max(castpoint, cooldown)` (`ActiveSkill.as:62-74`).
- `m_frozen` gates skills only; movement still updates (`CompositeActorBehavior.as:1199`, `:1245`).
- `gl timescale` exists; player movement does not scale (floor-soak 20261017-175501).
- In-game chat's TextInput exists only in the main menu (`MainMenuGameMode.as:62`); test
  `PlayerStashEditWindow`'s TextInputWidget in-session instead.
- Per-skill damage counts only when `di.Weapon != 0` (`Player.as:205-208`).
- Resource files are cached at boot (RE_NOTES, inbox-reload 20261018-010933).

## Decided during build

1. **The dock is an immediate-mode overlay**, not a WindowManager window. The Dev Arena module
   draws it from `RenderWidgets` (SpriteBatch rectangles and text, the HUD's `gui/fonts/hw8.fnt`),
   as `Modules/DebugModule.as` draws its overlays, and does its own hit-testing, so the game keeps
   running. Mouse capture: only while the pointer is over the open dock, the module takes
   `Focus::Obtain(PLAYERMENU)`, which is what an open game window does (`GUI/WindowManager.as:146`).
   For that time the player reads no attack, skill, aim or movement input (`Player.as:1282-1283`).
   Clearing `GameInput` fields from the module instead would depend on the module order. Off the
   dock, nothing is taken. Verified by spike-dock (see `docs/RE_NOTES.md`).
1a. **Resolution: it must look right at 1080p and 1440p** (user, 2026-10-20). All layout is in
   the engine's UI units (window px / `m_wndScale`, the HUD's units), so the dock keeps its size
   relative to the HUD at any resolution and follows `ui_scale`.
   - Row heights come from the font's line height.
   - Width is 35% of the UI width, clamped to at least 260 and at most 50%.
   - Rect edges and text origins snap to whole window pixels, because scales are fractional.
   - Panels are near-black, because colours render brighter than their values (assumed: a gamma
     step, from the spike-dock shot).
   - No layout constant is in window pixels.
   - The 1080p/1440p visual check is a heavy run and goes at the end (user: big tests last).
   - The HUD's bottom bar draws over the dock, so where they overlap the dock stops 34 units
     above the bottom (measured bar: about 142 units each side of centre, 30 tall).
   Verified: res 20261021-022008 (`gamelab/scenarios/devarena/res.json`, every tab shot at
   1920x1080 = 960x540 UI units at scale 2, and 2560x1440 = 854x480 at scale 3, set in
   session by `gl da-res`). The first run, 20261021-021235, showed the Loadout footer over
   the HUD's pet icons at 1440p; that is fixed. Tune's REFS rows sit below the fold at 1440p
   and are reached with the wheel.
2. **The override file is an `.sval` inside the mod**, read with `Resources::GetSValue`. The game
   logs every override event; a Python tool (`tools/devarena/`) writes the file.
3. **HP1 uses castpoint 150 -> 100**, because Entangle's castpoint is 150, not 250
   (`players/ranger/skills/nature_entangle.sval`). In `PlayerSkillDirectional`, `castpoint` gates
   only the mana payment and the cooldown start; the cast action fires from the `timeline` entry
   (`[0,"start",150,"cast"]`). So the tuner's castpoint field also moves every timeline entry
   that equals the old castpoint (`castpoint` plus every matching `timeline` time; tuner-dock
   20261020-225735: 150 -> 100 moved `da-skill` `timeline.1` to 100).
4. **`da-set` is spike and setup plumbing.** It takes the same path as the dock's edits
   (`Tuner.as` `Commit`, then `Flush`): validate now, then apply on the first frame no class skill
   is casting, with one `LoadSkills()` per flush.
5. **Freeze is three locks.** It sets `m_frozen` (skills) and applies a code-built buff (lock-movement,
   lock-rotation, speed-mul 0, disarm, silence, 2 s), re-applied every second while on. Every
   frame it also zeroes each body's velocity, makes it static and pins it to its frozen position.
   The first two locks alone let mobs drift about 3.9 px in 10 s, from pushes and knockback
   (spike-freeze 20261020-222234 and -222411). With all three: maxMoved 0.0 (20261020-222630).
   "Off" makes the bodies dynamic again (`Freeze.as`).
6. **Dock text fields arm text input the way the chat does.** A field uses `ExpectTextInput`
   and the window manager's input lock, then reads the `GameInput` text events. Enter commits,
   Escape reverts and a click elsewhere commits. GameLab's `!...~` inbox frames are skipped, so
   "!" and "~" cannot be typed. Verified by spike-text 20261020-224031. The slider and stepper
   fallback is not needed.
7. **RNG: statistics only.** Draws taken a few frames after `srand` do not repeat
   (spike-rng 20261020-222702), so the bench never relies on a fixed seed.
8. **Versions are append-only; the first edit makes B.** A version is the whole edit list on top
   of vanilla (v0). Every commit adds one, so A/B and undo/redo are only version indices and a
   commit after an undo adds a new version instead of dropping the redo tail. While B is empty,
   the first commit makes B and switches to it, which keeps A as the champion.
   Ctrl+Z/Ctrl+Y step the live slot's pin. F2 swaps slots. Verified by tuner-dock 20261020-225735.
9. **The override line is the whole state.** On every change the game logs
   `[HWP:devarena] override {"schema":1,"live","a","b","slot","pins","versions":[{"note","edits":[[skill,level,path,value]]}]}`.
   `tools/devarena/overrides.py sync [--follow]` writes the last such line to
   `mods/devarena/tweak/hwp/devarena_overrides.sval`, which is read once at boot. The committed
   file is empty (vanilla). Verified by export-boot 20261020-230402: back on v3 in B with its pin.
10. **Export to vanilla = the `vanilla-tuning` mod, which replays edits at runtime.**
    `tools/devarena/export.py --version N|live|a|b` writes one version's rows to
    `mods/vanilla-tuning/tweak/hwp/vanilla_tuning.sval`. The mod patches each named skill def
    once (with a generated copy of `Patch.as`, kept in sync by a test), then calls `LoadSkills`.
    It shadows no base file, because `gamecode/datatables/*.sval.json` is lossy: vectors dump as
    float arrays and the preprocessor includes are already expanded.
    Off unless enabled on a save; never enable it together with `devarena`.
    Verified by export-boot 20261020-230402 (ran_mark cooldown 1234, castpoint 77).
    Exporting a spec mod (`spec-<id>`) waits for the composer step.
    **Superseded 2026-10-26 (user):** HammerwatchPlus does not rebalance vanilla classes, so
    `vanilla-tuning` is gone. `tools/devarena/export.py` now bakes a version into the skill
    files of the mods that own the tuned skills (the 4th specs, Firearms, the HoH1 classes),
    with `clone_spec.patch_leaf` and the tooltip rewrite; it refuses vanilla skills.
11. **Clicking a field selects its value.** The first typed character or Backspace replaces it,
    as in a spreadsheet cell.
12. **Scenarios click dock buttons by id**, as `{"do":"click","dock":"<id>"}` in `gamelab/ui.py`,
    aimed through `gl da-dock`'s button map. The layout can then move without breaking any
    scenario. The fixed-pixel spikes `spike-dock` and `spike-text` came before this and are
    superseded by tuner-dock.
13. **Presets are generated rows, read once at boot.** `tools/make_presets.py` writes
    `mods/devarena/tweak/hwp/devarena_presets.sval`: 24 subclasses x early/mid/end (level 5/12/20,
    common/uncommon/rare gear at ilvl 5/12/20, 2/4/6 trinkets), plus the hand variants in
    `tools/devarena/presets_hand.json`. 74 in all. A preset is a class, a level and rows: `stat`,
    `skill`, `combo`, `equip`, `trinket`. Stars and stat points are spent in full (3 per level).
    Masteries are left out. `--check` fails when the file is stale.
14. **Applying a preset changes the class in place.** It resets the record, calls `ChangeClass`
    when the class differs, sets XP for the level, spends stats and skill picks, and equips
    seeded gear: `srand(HashString(id))`, so a preset always rolls the same mods. Equipment
    requirements are off while it equips. Then it adds trinkets, refreshes, and reads every row
    back (`loadout <id> ok|mismatch ...`). There is no floor reload. The class, the HUD skill
    bar and the readback are verified (loadout-all 20261020-233249). The re-skinned sprite is
    assumed: 640x360 shots are too small to show it.
15. **Edits are made inline in the sheet, not in a separate editor.** The sheet's steppers
    (level, stats, skill and combo picks) change the live build. A row that differs from the
    preset is marked `*`, and the mini HUD shows `DEV | <preset>*`. A refused step (no points
    left, a skill at its cap) is logged with `refused:` and changes nothing. Revert re-applies the
    preset. The dock widens to 45% on this tab and splits into two columns at 300 px.
16. **Variants and favorites persist the way tuner state does: through the log.** Save variant
    logs `loadout-variant {...}` (the whole build), and a star logs `loadout-favorites [...]`.
    `tools/make_presets.py --import-log LOG` folds them into the hand file as set/drop/add rows
    against the preset they came from, and a re-imported id becomes `+e2`. They are in the preset
    file on the next boot.
17. **The tooltip lint binds by value, not by name.** `tools/devarena/tooltip_lint.py` binds each
    `description-params` number to the level fields that show it at every vanilla level
    (equal; ms as "Ns"; a fraction or a percent as "N%"). It then reports the params a version's
    edits leave behind. Vanilla: 378 skills, 369 params bound, 173 not, 0 stale. Level L reads
    `upgrades[L-2]` and then the base, and upgrades do not stack (PlayerBase.as:179-187).
18. **F3 resets the arena, not the floor.** It kills what the brush placed, clears the
    encounter list and gives a fresh golem (debuffs off, then the picked ones on). Reload
    regenerates the floor from the same generation seed (`GameLab::g_genSeed`) and the NG+ picked
    on the tab. It fires 10 frames after the click: a level change in the middle of a press left
    `MenuInput.Forward.Pressed` set for good, and the dock on the new floor took it as another
    Reload, three a second (arena-dock 20261020-235104). For 10 frames on a new floor the dock
    also ignores clicks and clears a held press.
19. **Arena state rides the town save.** Script globals and `CVars::Cht*` reset on a level
    change, so god, no-cooldown, free mana, speed, the mob toggles, brush kind, golem
    profile/pool/NG+/debuffs, the open tab and the dock go into the town save under
    `hwp-devarena-arena` (`TownRecordSave`/`TownRecordLoad` hooks, the way gamelab-hands keeps
    the generation seed). The cheats are re-applied on every new floor. Verified by arena-dock
    20261020-235731: after Reload, `cvarGod`/`cvarNocd` true, same seed and start, dock back on
    the Arena tab. The armed brush unit is not kept.
20. **Unkillable is hp floored at 1 each frame, not immortality.** Burst over a mob's whole pool
    in one frame still kills it (assumed; not measured). Passive clears `m_targeting` and the
    target every frame.
21. **The brush places with the middle button; Esc disarms through the HUD.** A middle press
    off the dock places the armed unit or encounter (single 1, pack 4, swarm 13) at the
    pointer's world point; a pack or swarm is a ring around it. GameLab's emulated mouse adds
    `pointer <x> <y> mclick` (gamelab-hands, one counter and the press point). That the
    engine's middle button is index 2 is assumed (SDL); only `mclick` was measured. Esc goes to
    `MenuBack`, which asks HUD components first (HUD.as:538-547), so a drawless `EscGuard`
    at the head of the HUD's list takes it while armed. Without it Esc disarmed and opened the
    pause menu too (arena-dock 20261020-235519); with it, no menu (20261020-235731).
22. **The golem room is built where F4 is pressed.** F4 snaps that spot to the 16-unit grid,
    rings a 224 x 224 box with the barracks' own wall pieces (`doodads/walls/barracks/h_32` /
    `v_32`, 28 of them), moves the player 48 south of the centre and the golem 48 north; while
    inside, every other enemy within 300 units is culled each frame. F4 out destroys the walls
    and returns the player. The room starts at the floor's start, which on dark_citadel 13 seed
    4242 is a 32-wide niche, so stand somewhere open first. Verified by golem-room
    20261021-000718: walking east 3 s stopped at dx 106 against the wall at 112, with the
    corridor going on past it (`atWall "e"`, shot `against-wall`). The golem is a unit from a profile
    (target dummies, guard elites, knight) with a fixed pool (unit/1M/4M/10M), NG+ scaling
    turned off, and armor and resistances baked for the picked NG+
    (`Tweak::EnemyNGPArmorMul` 0.66, Data/Misc.as:42). It is frozen and never targets.
23. **A pull is damage dealt to the golem, ended 4 s after the last hit.** Damage is the drop
    in hp each frame. Per-skill rows come from the `PlayerDamagedActor` hook (`di.Weapon`
    matched to the player's skills), and the rest is an "unattributed" row. The end logs
    `golem-pull {golem, ngp, pool, end, dealt, ms, ttk, dps, hits, skills, preset, version}`.
    Verified by golem-room 20261020-235415: ranger main attack, 1719 dealt in 3894 ms, 441 dps,
    28 hits, attack_2h_shortbow 1037 + nature_wind_weaver 682, unattributed 0. Hitting the
    golem counts toward the game's own stats: that pull unlocked "Heavy Hitters I" in the lab
    save. Use a dev save.
24. **The bench (Bench tab, `Bench.as`) is N pulls per side, interleaved A B A B.** Sides are
    the tuner's A/B slots or two loadouts ticked on the Loadout tab ("Bench these"). Each pull
    switches the variant, respawns the golem, zeroes cooldowns, fills mana and stands the player
    24/48/74 below the golem (chip; 24 so melee reaches: paladin_divine/early went 24 -> 127 dps).
    Drivers: bot (priority rules), me (records Down edges of the first pull), replay. Moving or
    pressing a skill aborts. AOE skills are placed on the golem by the engine's own confirm
    branch, because the bot has no mouse (PlayerTargetingHelper.as:288-299). A press that leaves its skill
    still ready 400 ms on backs that button off for 2 s and logs `bench-stuck` (seen:
    paladin `divine_pillars`, `pal_blessed_strikes`; why they do not cast is not explained).
    While a bot or replay bench runs, hovering the dock does not take menu focus, or the
    player is frozen after clicking Start. The stats are mean, sd, n for +-3% and a Welch verdict. The
    game's numbers are re-checked by `tools/devarena/bench.py` in the `bench_csv` runner step.
    Fixed-seed mode was not built (the RNG spike). Verified: bench-dock 20261021-004821,
    hp2-golem-tuning 20261021-003613, hp3-loadout-compare 20261021-003510,
    bench-baseline-smoke 20261021-004659. Entangle area damage varies 75-2490 between
    identical pulls (observed; not explained). The 72-preset baseline
    (`devarena/bench-baseline`, generated by `tools/devarena/make_baseline_scenario.py`) ran in
    bench-baseline 20261021-022359 (PASS, 1263 s); `bench.py baseline` wrote its 72 rows into
    `tweak/hwp/devarena_baseline.sval`.
25. **A composed skill is one tuner edit that replaces a learned slot.** The Compose tab builds a
    draft (start: projectile or nova template, or a clone of a vanilla skill's base; a catalog
    projectile; cast and start snippets; damage type; status; name; castpoint, cooldown, mana,
    main damage) and CHECK validates it before Apply. The draft is the edit
    `{slot, level 0, "@compose", draft}`, so versions, A/B, Tune and Bench treat it like any other.
    Applying it puts the built dict in level 0 and cuts levels 1.. and the slot's modifier
    sub-skills down to their skill-cost, because AddPlayerSkill stacks them on the base
    (PlayerBase.as:189-215). The slot keeps its id, icon and hotkey. The catalog
    (`tweak/hwp/devarena_compose.sval`) is generated by `tools/devarena/make_compose.py` and holds
    only projectiles whose unit reads binds the template sets. The game logs the built dict
    (`compose-dict`) so tools can bake it. Verified: hp4-compose 20261021-011713.
26. **[Relaunch] is a saved state plus a runner restart.** The game cannot restart itself. The button
    saves, logs `[HWP:devarena] relaunch {...}` (preset, tab, floor, seed, position, trinkets),
    and the runner's `relaunch` step syncs the override file from the log, quits and boots the
    saved session. On boot the mod re-enters the same floor and seed and restores the player.
    The trinkets ride in the dict because the boot's MissionEndMenu clears them
    (GUI/MissionEndMenu.as:428). Verified: hp5-relaunch 20261021-013132.
27. **The ship check is the real NPC, read back by `da-ship`.** `tools/devarena/clone_spec.py`
    writes `mods/spec-<id>` from a tuner version and rewrites each copied skill's tooltip rows
    to its new numbers (a row whose fields a compose removed is dropped). hp6-ship builds the
    guild hall to tier 3, which is where the Subclass Picker stands (`guild_hall_tier_3.pfb` and
    up), with a level-10 ranger (the NPC offers the picker at `lvl ge 10`). The player presses Use
    on the NPC, tours the picker's next arrow through every sibling and takes the spec with
    MenuContext (R). `da-ship` reports the class as parsed (names resolved, parent, picker slot,
    skills, the window's texts). `tools/devarena/ship_check.py` combines that with the spec
    tooltip lint into `docs/devarena/ship/<id>.md`. Verified: hp6-ship 20261021-014726.
28. **The auto-tuner proposes; the player accepts.** `gamelab/bots/devarena_autotune.py` over
    `tools/devarena/autotune.py` takes 1-3 fields (`<skillId>:<path>`, optional bounds) and a dps
    target vs A (`+15%`). It refuses feel-locked fields (castpoint, timeline, cooldown,
    move-speed-mul, blocking, anim) unless unlocked by name. Per field it reads the player's level
    (`da-skill`; levelIndex = level - 1, PlayerBase.as:187), tries a ladder of multiples nearest
    first, each one `da-set` into B and benched with the dock's own Start bench, and bisects
    between the last miss and the first hit. A hit needs the delta and the bench's verdict
    ("B better"). The hit is filed with `da-propose`; `Proposal.as` keeps it with its bench-result
    as evidence and logs `autotune-proposal`. The Bench tab shows it as PENDING with Accept
    (Keep B>A) and Discard (Discard B), logged `autotune-accept`/`-discard`. One proposal at a
    time; it does not survive a relaunch (assumed fine: the tuner re-runs in minutes).
    `tools/devarena/autotune.py --run <dir>` writes `docs/devarena/proposals/<run>.md`.
    Verified: hp7-autotune 20261021-015752 (ran_mark proj-dmg 50 to 200, +33.4% then +28.1% dps
    on footman elite NG+3, bot; the first proposal discarded, the second accepted).
